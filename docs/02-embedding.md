# 02 · 嵌入与位置编码：给每个 token 一个坐标和座次

> 对应模块：站点左侧「② 嵌入与位置编码」

## 一句话

嵌入把离散的编号变成连续的向量，让"相似"这件事可以被计算；位置编码把语序补回去，因为**自注意力本身是排列等变的——把句子打乱，它根本察觉不到**。

## 嵌入：从"编号"到"坐标"

分词之后每个 token 只是一个整数。问题在于：**整数之间没有任何可计算的关系**。id 5 和 id 6 不代表它们更像，id 5 和 id 5000 也不代表它们更不像。

嵌入层做的事情就是一张查找表：

```
X = Embedding[token_id]     形状 [n, d_model]
```

给每个 token 分配一个 `d_model` 维的向量。这些向量是**训练出来的**，训练目标会让语义/用法相近的词在向量空间里靠拢。经典的例子是 `king - man + woman ≈ queen`。

这里常被忽略的一点：**嵌入矩阵通常是模型里最大的单块参数之一**。

```
参数量 = 词表大小 × d_model
LLaMA 3: 128256 × 4096 ≈ 5.25 亿（仅嵌入层）
```

而且最后输出层还要一个同样大小的 unembedding 矩阵（有些模型会做权重绑定）。这就是为什么词表大小是个需要谨慎权衡的超参。

## 为什么必须额外加位置信息

看一眼注意力的核心公式：

```
Attention(Q, K, V) = softmax(QKᵀ / √d_k) · V
```

`Q`、`K`、`V` 都来自同一个输入 `X`。如果你把 `X` 的行顺序打乱，`Q`、`K`、`V` 的行会以同样的方式打乱，`QKᵀ` 的结果也会以同样方式打乱，**最终输出的每一行也会跟着同样打乱**。

也就是说：注意力把每个位置当成"集合里的一个元素"，而不是"序列里的第 i 个"。它看不出"猫追老鼠"和"老鼠追猫"的区别——除非你告诉它顺序。

所以位置编码不是"锦上添花"，是**必需项**。

## 方案一：正弦位置编码

原始 Transformer 的做法，完全不需要学习：

```
PE[pos, 2i]   = sin(pos / 10000^(2i/d))
PE[pos, 2i+1] = cos(pos / 10000^(2i/d))
```

设计上有个很漂亮的性质：**不同维度对应不同频率**。

- `i` 小 → 分母接近 1 → 频率低 → 波长长，能覆盖整个序列
- `i` 大 → 分母巨大 → 频率高 → 相邻位置的值就天差地别

类比一下：就像用一组不同周期的钟表来编码时间——有的表一天转一圈（能区分上午下午），有的一年转一圈（能区分季节）。组合起来就能唯一确定时刻。

还有一个关键性质：**PE[pos+k] 可以表示成 PE[pos] 的线性函数**（用旋转矩阵）。这意味着模型可以学到"相对距离 k"，而不只是"绝对位置 pos"。

在站点的「位置向量相似度」热图里，你能看到明显的**对角条带**——相似度只取决于两个位置的距离，而不是具体第几位。这就是相对位置感的来源。

**缺点**：正弦编码是"加"在嵌入上的绝对位置，模型得自己学会从中推断相对关系；而且它的外推能力差，训练时最长 512，推理时给 4096 就崩。

## 方案二：RoPE 旋转位置编码

现在 LLaMA、Qwen、Mistral 全在用。思路完全不同——**不是加一个向量，而是把向量本身转一个角度**。

把 `d` 维两两分组，第 `j` 组在位置 `pos` 处旋转：

```
θ = pos / 10000^(2j/d)
```

具体做法是作用在 query 和 key 上：

```
q̃ = R(θ_pos) · q
k̃ = R(θ_pos') · k
```

妙处在于点积：

```
q̃ᵀk̃ = qᵀ R(θ_pos)ᵀ R(θ_pos') k = qᵀ R(θ_pos' - θ_pos) k
```

**结果只依赖于相对距离 `pos' - pos`。** 相对位置不是"学出来的"，是数学上直接保证的。

这就是 RoPE 外推能力更好的根源：模型从没见过"相对距离 5000"，但只要它见过"旋转这么多角度"，就能处理。

在站点的 RoPE 演示里，拖动"维度组 j"：

- `j = 0`：射线几乎不转（低频），能表达很长的距离
- `j` 拉大：射线飞转，相邻位置就差很远，只能区分近处

## 为什么长上下文外推这么难

顺着 RoPE 往下想就明白了。训练时模型只见过 `pos ∈ [0, 4096]` 范围内的旋转角度。推理时突然给 `pos = 32768`，那些低频维度转过的角度是训练时从未见过的——模型不知道该怎么办。

于是有了各种外推方案：

- **PI（位置插值）**：把 pos 缩放一下，塞回训练见过的范围
- **NTK-aware**：对不同频率维度用不同的缩放系数（高频少缩、低频多缩）
- **YaRN**：再加一层注意力温度修正

这些方案的本质都是在回答同一个问题：**怎么让"没见过的角度"落在模型能理解的区间里。**

## 常见误解

**"位置编码是加在嵌入上的，所以是一个向量加一个向量"** —— 正弦编码是这样，RoPE 不是。RoPE 不改变向量本身，它改变的是**计算 attention 时 q 和 k 的旋转状态**。

**"相对位置一定比绝对位置好"** —— 大多数情况是这样，但绝对位置在某些任务（比如需要知道"这是第几段"）上有用。有些模型会两者都用。

**"位置编码让模型知道词序"** —— 更准确的说法是：它让注意力**有机会**利用词序。信息被注入了，模型要不要用、怎么用，是训练决定的。

## 在站点上怎么玩

1. 在「嵌入向量」热图里看每个 token 的行——注意首字符相同、类别相同的 token 会有相似的颜色块
2. 在「正弦位置编码」热图里横向看：左边几列几乎不变（低频），右边剧烈震荡（高频）
3. 在「位置相似度」图里找对角条带，验证"相似度只跟距离有关"
4. 在 RoPE 演示里拖动维度组，观察射线转得快慢的差别
5. 看 PCA 散点图，理解"高维语义压到 2 维"会损失多少信息
