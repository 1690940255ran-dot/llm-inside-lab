# 04 · 采样：温度、top-k、top-p 分别在改什么

> 对应模块：站点左侧「④ 逐 token 生成与采样」

## 一句话

模型每一步只做两件事：**算出一个词表上的概率分布，然后从中抽一个 token**，再把这个 token 拼回输入继续。三个参数改的都是"抽签之前那一步"。

## 完整链路

```
logits ──(÷ 温度 T)──▶ softmax ──(top-k 截断)──▶ ──(top-p 核采样)──▶ 重新归一化 ──▶ 抽签
```

注意顺序：温度作用在 **logits** 上，top-k / top-p 作用在 **概率** 上。这个区别很重要，下面会讲。

## 温度

```
p_i = exp(logit_i / T) / Σ_j exp(logit_j / T)
```

- **T → 0**：分布趋近 one-hot，等价于贪心解码
- **T = 1**：模型原本的分布
- **T > 1**：长尾被抬起来，输出更发散

直觉上：温度是在调"分布有多平"。**它改变的是整个分布的形状，而且是连续地改变**——所有候选的概率都会动，只是动的幅度不同。

一个常见的错误理解是"温度控制随机性"。更准确的说法是：**温度控制模型对自己判断的自信程度**。T 很低时，模型会坚持选它认为最优的那个；T 高时，它愿意赌一把。

## top-k

只保留概率最大的 `k` 个，其余直接置零后重新归一化。

- `k = 1`：就是贪心
- `k` 小：稳但单调，容易复读
- `k` 大：多样但容易跑偏

**top-k 的问题**：`k` 是固定的，不看分布长什么样。

模型很确定的时候（比如"中国的首都是___"，正确答案是"北京"占 95%），`k = 50` 会强行把 49 个垃圾候选拉进来；模型很纠结的时候（比如开放式续写），`k = 5` 又会把合理的长尾砍掉。

## top-p（核采样）

从大到小累加概率，保留累计概率**刚超过 p** 的最少候选：

```
排序：p₁ ≥ p₂ ≥ ... ≥ p_V
找到最小的 m，使得 Σ(i=1..m) pᵢ ≥ p
保留前 m 个
```

**候选数自适应**：模型确定时只留 2 个，纠结时留几十个。这就是它比 top-k 优雅的地方。

实现上有个细节：那个"跨过阈值"的候选要保留（否则累计概率会不够 p）。站点的实现遵循这一点。

## 温度 vs top-p：关键区别

这一点值得单独强调，因为混用它们是最常见的调参错误：

| | 温度 | top-p / top-k |
| --- | --- | --- |
| 作用对象 | logits（softmax 之前） | 概率（softmax 之后） |
| 改变方式 | 连续缩放整个分布 | 直接砍断分布的支撑集 |
| 效果 | 所有候选概率都变，长尾相对抬升/压低 | 长尾直接归零，剩下的重新归一化 |

**在站点的候选表里，这两者的区别一眼可见**：被 top-k / top-p 砍掉的候选整行变灰（概率显示 `—`），只是被温度压低的候选数字变小但还在。

所以：

- 想要"更保守但别太死板" → 调低温度
- 想要"砍掉明显不靠谱的长尾" → 调小 top-p
- 两个都猛调 → 等价于贪心，会迅速陷入复读

## 工程实践里的常见配置

| 场景 | 推荐 |
| --- | --- |
| 代码生成 | T = 0.2，top-p = 0.95 |
| 事实问答 | T = 0（贪心）或 T = 0.1 |
| 创意写作 | T = 0.8~1.0，top-p = 0.95 |
| 需要多样性 | T = 1.0+，top-p = 0.98 |

一般**不要同时开很强的 top-k 和很低的温度**——两个都在往贪心靠，叠加起来输出会更死板。

## 为什么低温度会复读

这是最容易被观察到的失败模式。机制其实很简单：

1. T 很低时，每一步几乎必选概率最大的 token
2. 一旦进入一个模型见过的常见短语，后续的最优选择高度确定
3. 模型就沿着这条"最优路径"走到底，甚至开始循环

温度调高会打破这个确定路径，但代价是可能偏离主题。**这也是为什么 top-p 流行**——它只在模型真正纠结的地方引入随机性，在模型确定的地方保持坚定。

## 关于可复现性

站点里给了"随机种子"滑块。同一个种子 + 同一组参数 = 完全一样的结果。

生产环境里这个很重要：

- 调 prompt 时固定 seed，才能公平对比
- 出线上 bug 时，需要 seed 才能复现
- 但注意：**即使固定 seed，不同 batch size / 不同硬件下结果也可能不同**（浮点累加顺序的影响）

## 常见误解

**"temperature = 0 就是贪心"** —— 数学上 T=0 是未定义的（除以零）。实现上 T→0 的极限确实等价于贪心，所以 API 一般允许传 0，但内部会做特殊处理。

**"top-p 和 top-k 二选一"** —— 可以叠加，顺序是先 k 后 p。但一般没必要。

**"采样只会影响文风"** —— 在推理任务（数学、代码）上，采样策略会显著影响正确率。这也是为什么 benchmark 通常用贪心或极低温度。

## 在站点上怎么玩

1. 把温度调到 0.1，点"重新采样 5 次"——5 条几乎一模一样（复读机模式）
2. 调到 2.0 再采样——5 条各不相同，但开始胡言乱语
3. 固定温度 1.0，把 top-p 从 1.0 拖到 0.3，观察候选表里变灰的行越来越多
4. 看"保留候选数"这个指标：它随 top-p 变小而下降，但随温度变化**不变**（因为温度不改变支撑集）
5. 对比"原始 p"和"采样后 p"两列，理解重新归一化做了什么
