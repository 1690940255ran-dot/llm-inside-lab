## 一条主线

大模型做的事实上只有一件事：**根据前面的 token 预测下一个 token**。

沿着这条线往前推，会自然推出六个模块：

```
要预测下一个 token
  └─ 得先把文本变成数字          → ① 分词
      └─ 变成向量，还得带上顺序    → ② 嵌入与位置编码
          └─ 让 token 之间能交流  → ③ 注意力
              └─ 一层不够，堆很多层 → ⑥ Transformer Block
                  └─ 最后输出一个分布 → ④ 采样（决定抽哪个）
                      └─ 一个一个往外蹦，太慢了 → ⑤ KV Cache
```

## 第二条线：把模型做大、做小、做长

前六个模块是"一个 token 怎么走完全程"。后三个模块是工程上真正花力气的地方——**把模型做大（MoE）、压小（量化）、拉长（上下文外推）**：

```
想让模型更强，但不想等比烧算力
  └─ 把 FFN 拆成一堆专家，每个 token 只走几个 → ⑦ MoE
      └─ 总参数上去了，显存就成问题           → ⑧ 量化
          └─ 上下文也想要更长，但 4K 喂不动 32K → ⑨ 长上下文外推
```

这三个模块比前六个**更"脏"**：前六个都有干净的解析答案，后三个全是权衡——MoE 的均衡力有最优强度、量化的 group size 有上下限、外推方法在局部精度和长程分辨力之间必须二选一。而且它们的结论**必须靠实测**，站点里每一张曲线都是从真实公式算出来的。

## 关于"模拟"这件事

站点里所有数值都是确定性的模拟结果，不是真实模型的前向输出。这一点在每一篇的开头都会被提醒一遍。

需要强调的是：**被模拟的只有"学出来的权重矩阵"，算法流程全是真的**。

- BPE 的合并表是从语料频次里真数出来的；
- 注意力的 Q/K/V 投影、`/√d_k` 缩放、因果掩码、softmax 走的是完整正确的路径；
- 采样三个参数的实现和 HF `transformers` 里的 `TemperatureLogitsWarper` / `TopKLogitsWarper` / `TopPLogitsWarper` 逻辑一致；
- KV Cache 的复杂度分析是解析推导，可以直接和 profiler 对照；
- MoE 的路由训练、容量淘汰、aux 梯度、偏置反馈都是逐步迭代算出来的，负载倾斜是涌现的；
- 量化的电平、code、scale、SQNR、每权重字节数都是真的算出来的；
- 上下文外推的角频率、波长、别名起点、几何视野都由 RoPE 公式直接推出。

所以用它**建立直觉**是安全的，用它**引用具体数值**是不行的。
