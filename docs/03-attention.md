# 03 · 多头注意力：模型到底在看哪里

> 对应模块：站点左侧「③ 多头自注意力」——本项目的主力模块

## 一句话

每个位置带着自己的问题（Query）去和所有位置的名字牌（Key）比对，按匹配程度把大家的内容（Value）加权平均过来。**多个头并行做这件事，每个头关注的角度不同。**

## 完整公式

```
Q = X · W_Q      [n, d_model] → [n, d_model]
K = X · W_K
V = X · W_V

scores  = Q · Kᵀ / √d_k       每个 query 对每个 key 打一个原始分
scores += 掩码（未来位置 → -∞） 因果语言模型不能偷看后面
weights = softmax(scores / T)  归一化成"注意力预算怎么分"
output  = weights · V          按权重把信息取回来
```

多头版本就是把 `d_model` 切成 `h` 份，每份 `d_k = d_model / h` 维，各自独立算一遍，最后拼接 + 线性变换。

## 为什么要除以 √d_k

这是最常被追问的细节，也是面试高频题。

假设 `q` 和 `k` 的每个分量都是均值 0、方差 1 的独立随机变量。那 `q·k` 是 `d_k` 个这样乘积的和，方差就是 `d_k`，标准差是 `√d_k`。

**维度越高，点积的绝对值越大。** 当 `d_k = 512` 时，点积的典型量级是 ±23 左右。

然后这些数被送进 softmax。softmax 对输入的尺度极其敏感——输入差距一大，输出就被推到 0/1 两端，梯度几乎为零，**训练直接停滞**。

除以 `√d_k` 相当于把方差拉回 1，让 softmax 工作在它最舒服的区间。

在站点里把"温度 T"调到 0.3 再调到 2.0，你看到的就是**不除以 √d_k 时发生了什么**——分布被推到极端，几乎所有权重集中在一两格上。

## 为什么要多个头

单头注意力的根本限制：**它只能表达一种关系**。

一个 `n × n` 的注意力矩阵是"平均主义"的：每一行必须归一化成和为 1，所以如果一个位置需要同时关注"前一个词"和"语义相关的词"，单头只能把权重摊在两者之间，得到一个模糊的折中。

分成多头之后，每个头只需要专注于一种关系：

- 有的头专门看前一个 token（学二元语法）
- 有的头盯句首（attention sink，见下）
- 有的头抓标点——这些位置往往聚合了整句的概括信息
- 有的头做内容相似匹配（深层常见，用来做指代消解）

**在站点的「本层所有头一览」里，你会看到几个缩略图的图案完全不同。** 这就是多头存在的意义，比任何文字解释都直观。

## Attention Sink：一个反直觉但极重要的现象

真实大模型里有个普遍现象：**大量注意力权重被无脑丢给第一个 token（通常是 `<BOS>`）**，哪怕它在语义上毫无意义。

原因其实可以从 softmax 的性质推出来：softmax 的输出必须和为 1，也就是说**每一行的注意力预算必须花光**。如果某个位置"没什么值得看的"，模型也得把这份预算花出去，于是就找到了一个永远存在的兜底目标——第一个 token，因为它在因果掩码下对所有位置都可见。

站点的指标区给了「句首 sink 占比」这个数字，切到不同的头看看它的变化。

这个现象有巨大的工程价值：**StreamingLLM** 正是基于它实现了无限长上下文——只要永久保留首 token 的 KV，再配一个滑动窗口，模型就能稳定处理远超训练长度的序列，而不需要重训。

## 头的行为是"学出来的"还是"设计出来的"

是从数据里学出来的，但**学到的模式高度可复现**。文献里反复观察到的典型模式包括：

| 模式 | 说明 |
| --- | --- |
| Previous token | 只看前一个词，等价于 bigram 统计 |
| First token / sink | 大量权重压在句首 |
| Delimiter | 盯逗号句号，这些位置常聚合了整句概括 |
| Positional / diagonal | 对角线，关注自身或邻近 |
| Content matching | 语义或拼写相似（深层常见） |
| Sparse induction | 只被少数特定 pattern 激活，像关键词检索 |

站点的模拟正是把这些已知模式作为"头行为偏置"注入的，所以你看到的图案不是随机噪声，而是**对真实观察结果的复现**。

## 因果掩码为什么不可省

训练时我们用的是"预测下一个 token"这个目标。如果第 `i` 个位置能看到第 `i+1` 个位置，模型就能直接抄答案，训练目标失效，学到的东西在推理时完全用不上。

所以因果掩码（上三角置 -∞）不是"为了自回归而加的约束"，而是**训练目标本身的数学要求**。

在站点里关掉因果掩码再打开，看看热力图右上角的变化——关掉时那片区域有值，打开后变成斜纹（表示被遮挡）。

## 复杂度：注意力的原罪

```
时间：O(n² · d)      每个位置都要和所有位置比对
空间：O(n²)          n×n 的注意力矩阵要存下来
```

序列翻倍，计算量和显存都翻四倍。这是长上下文最核心的瓶颈，也是 FlashAttention、稀疏注意力、线性注意力这些工作的全部动机。

一个具体感受：序列长度 128K 时，单是注意力矩阵就有 `128000² ≈ 164 亿` 个元素。fp16 下就是 32 GB——**一层就放不下**。

## 常见误解

**"注意力权重 = 模型认为重要的东西"** —— 不准确。注意力只表示"信息从哪里流向哪里"，不等于"什么重要"。注意力权重高不代表那个 token 对预测贡献大，这是可解释性领域的长期争论。

**"多头越多越好"** —— 有明确的边际递减。头数太多时，很多头会学到重复的模式；而且每个头的维度 `d_k` 会变小，表达能力反而下降。

**"注意力是模型'理解'语言的地方"** —— 更准确的说法是：注意力负责**信息路由**（谁从谁那里拿信息），FFN 负责**信息处理**（拿到之后怎么加工）。两者分工不同。

## 在站点上怎么玩

1. 先看「本层所有头一览」，找图案差异最大的两个头，分别点开看
2. 拖动层数：浅层偏位置/局部（对角、前一个词），深层偏语义/全局
3. 把温度调到 0.3 和 2.0，感受分布尖锐度的变化
4. 关掉因果掩码，看右上角那片区域"活"过来
5. 拖动距离衰减到 0，看注意力会不会变成漫无目的的一片
6. 点某一行，看这个 token 完整的注意力分布和 top-8 目标
