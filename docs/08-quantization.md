# 08 · 量化：把 16 位压成 4 位，代价到底落在哪

> 对应模块：站点左侧「⑧ 量化」

## 一句话

量化的全部难点不在"怎么把浮点变成整数"——那只是一次取整；真正的难点是**一个 scale 要同时管多少个权重**。管的越多，离群值造成的破坏越大。理解这一点，就理解了 NF4、group-wise、per-channel 这一整条技术路线。

## 最基本的两种编码

**对称量化**（把 `[-maxabs, maxabs]` 均匀切成 `2^b` 级）：

```
scale = maxabs / qmax          qmax = 2^(b−1) − 1
code  = round(w / scale)       然后夹到 [−qmax−1, qmax]
ŵ     = code · scale
```

**非对称量化**（把 `[min, max]` 映射到 `[0, 2^b−1]`，多存一个 zero point）：

```
scale = (max − min) / (2^b − 1)
zero  = round(−min / scale)
code  = round(w / scale) + zero
ŵ     = (code − zero) · scale
```

非对称多存一个 zero point，但能处理分布整体偏移（比如 ReLU 之后的激活全为正）。权重一般近似零均值对称，所以对称就够用。

## 粒度才是主角

"一个 scale 管多少个权重"就是**粒度**：

| 粒度 | 一个 scale 管 | 典型场景 |
| --- | --- | --- |
| per-tensor | 整个张量 | 最省，最粗 |
| per-channel | 一行（一个输出通道） | 权重的默认选择 |
| group-wise | 行内再切 32/64/128 个 | GPTQ / AWQ / NF4 的标配 |

站点实测（4 bit、256 个权重）。**同样一组方案，有没有离群值，结论完全不同**：

**有 2 个 40σ 离群值（站点默认）：**

| 方案 | SQNR | 有效电平数 | 字节/权重 |
| --- | --- | --- | --- |
| INT4 per-tensor | **11.25 dB** | 5 / 16 | 0.500 |
| INT4 per-channel(8) | 17.98 dB | 15 / 16 | 0.531 |
| INT4 group=32 | 17.98 dB | 15 / 16 | 0.625 |
| NF4 group=32 | 18.93 dB | 16 / 16 | 0.625 |
| INT4 非对称 group=32 | **19.38 dB** | 16 / 16 | 0.625 |

**没有离群值（outlierCount = 0）：**

| 方案 | SQNR | 有效电平数 |
| --- | --- | --- |
| INT4 per-tensor | 17.80 dB | 15 / 16 |
| INT4 per-channel(8) | 19.70 dB | 15 / 16 |
| INT4 group=32 | 19.70 dB | 15 / 16 |

**把两张表对着看，才是量化最重要的一课：**

- 没有离群值时，per-tensor 到 group-wise 只差 **1.9 dB**——粒度只是"锦上添花"
- 一旦塞进两个 40σ 的离群值，同一个对比变成 **6.7 dB**（噪声能量差 4.7 倍），per-tensor 的有效电平从 15 个塌到 5 个

**所以"分组"的价值不是平均精度更高，而是把离群值的破坏范围限制在一组之内。** 它是一道隔离墙，不是一台更精密的秤。这也解释了为什么真实工作流里"先处理离群值"（AWQ、SmoothQuant、LLM.int8()）往往比"把 group 切得更小"更划算。

**关于"per-channel 和 group=32 数值完全一样"**：这不是巧合，也不是偷懒。本页的权重是一个 1D 序列，`per-channel` 就是把它切成 8 段（每段 32 个），和 `group=32` 的切法一模一样。真实权重是 2D 矩阵，per-channel 是按输出行切（一行一个 scale，一行通常上千个权重），group-wise 是在行内再切小段——**粒度比 per-channel 细一到两个数量级**，这才是"group-wise 普遍优于 per-channel"的真实由来。站点选择保留这个等价关系并把它写出来，而不是假装两种粒度不同。

## 离群值：4 bit 真正的敌人

把 2 个权重拉到 40σ，其它 254 个都不变，再看有效电平数：

| 离群强度 | 有效电平数 | SQNR | MSE |
| --- | --- | --- | --- |
| 1σ | 15 / 16 | 17.78 dB | 1.76e−2 |
| 10σ | 7 / 16 | 10.44 dB | 1.65e−1 |
| 40σ | **5 / 16** | 11.25 dB | **1.02e+0** |
| 100σ | **3 / 16** | 18.75 dB | 1.06e+0 |

看第三列和第四列：**MSE 一路变差（1.76e−2 → 1.02e+0，坏了 58 倍），而 SQNR 居然先掉后涨（17.78 → 10.44 → 11.25 → 18.75 dB）。**

这是量化里一个非常重要的陷阱：

> **SQNR 会骗人，MSE 和有效电平数不会。**

原因是 SQNR 定义成"信号能量 / 噪声能量"，而那个 40σ 的离群值自己就把分母（信号能量）撑大了。所以离群值越极端，SNR 反而"看起来越好"。

**这就是为什么看量化质量一定要看 MSE 或困惑度，而不是 SNR。** 站点里两个都给了，并把「有效电平数」单独抽出来——它最直观：本来 16 个电平，被 40σ 的离群值一挤，只有 5 个电平上还落着权重，**其余 11 个电平完全浪费（0 个权重落在上面）**，256 个权重实际只在 5 个值上取值。

### 为什么 group-wise 能救

分组之后，离群值只会毁掉**它自己所在的那一组**。上面那两张表已经把这件事量化了：同一组 32 个权重里有一个 40σ 的怪兽，这组的 scale 被撑大，但只有 32 个权重受害；其它 7 组完全没事。per-tensor 则是全张量一起陪葬。

NF4（QLoRA 的方案）更进一步：它不用均匀电平，而是**按正态分布的分位数**取 16 个非均匀电平——因为量化后的权重近似零均值正态，非均匀电平在正态分布下更贴合曲率。站点实测 NF4（18.93 dB）确实优于同粒度的对称 INT4（17.98 dB）。非对称（19.38 dB）还能再高一档，代价是多存 zero point。

## 显存账：别用 bits/8 算

这才是工程里最容易算错的地方。group-wise 量化**必须额外存每组的 scale 和 zero point**（各一个 fp16，共 4 字节）：

```
group=128  →  4/8 + 4/128 = 0.531 B/权重
group=32   →  4/8 + 4/32  = 0.625 B/权重   （多 18%）
```

站点实测（7B 与 70B）：

| 精度 | 字节/权重 | 7B | 70B |
| --- | --- | --- | --- |
| FP16 | 2.000 | 13.04 GB | 130.39 GB |
| INT8 | 1.000 | 6.52 GB | 65.19 GB |
| INT4 group=128 | 0.531 | 3.46 GB | 34.63 GB |
| NF4 group=64 | 0.563 | 3.67 GB | 36.67 GB |
| INT3 group=128 | 0.406 | 2.65 GB | 26.48 GB |
| INT2 group=64 | 0.313 | 2.04 GB | 20.37 GB |

几个可以记住的数：

- **7B 的 fp16 权重是 13.04 GB**（= 7e9 × 2 / 1024³）。这一步要牢记，因为它解释了为什么消费级显卡跑不动 7B——光是权重就超了 12G 卡。
- **7B INT4 group=128 是 3.46 GB**，而不是 `7e9 × 0.5 = 3.26 GB`。差的 0.2 GB 就是元数据。
- **再往下压，收益快速衰减**：INT3 比 INT4 省 23%，INT2 比 INT3 再省 23%，但精度损失是断崖式的（有效电平只剩 4 个）。这就是为什么社区主流停在 4 bit。

注意这里算的**只有权重**。实际部署还要加上 KV Cache（长上下文时可能比权重还大）、激活、以及 4 bit 反量化回 fp16 的临时缓冲。这就是为什么"能在 12G 卡上跑 7B INT4"是个需要仔细算的命题：3.46 GB 权重 + 8K 上下文的 KV Cache + 框架开销，往往就贴着 12G 的边缘。

## 常见误解

**"4 bit 量化就是精度掉一点"** —— 4 bit 只有 16 个电平。一旦出现离群值，有效电平可能掉到 5 个甚至 3 个，这时候**量化误差已经大到不是"掉一点"的程度**（站点实测 MSE 涨了 58 倍）。所以真实工作流一定是"量化 + 少量校准/微调"（QLoRA 的 LoRA 补丁就是干这个的）。

**"用 SNR 评估量化质量"** —— 站点实测已经展示了 SNR 的非单调性。用 MSE、困惑度，或者直接跑下游任务。

**"group size 越小越好"** —— 精度确实更好，但每权重元数据开销是 `4/groupSize`。group=32 比 group=128 多 18% 显存；group=8 就是 0.5 + 0.5 = 1.0 B/权重，**等于 INT8，量化省显存的意义彻底消失**。这是条鲜明的下限。

**"量化的收益就是省显存"** —— 还有速度。4 bit 权重的显存带宽占用是 fp16 的四分之一，而大模型解码阶段**几乎完全是显存带宽瓶颈**，所以量化往往能带来接近线性的解码加速。代价是要付出反量化的算力。

## 在站点上怎么玩

1. 先看默认配置（4 bit / 对称 / per-tensor / 40σ 离群值），注意直方图上那些竖线（电平位置）——大部分竖线周围一个权重都没有
2. 把 `离群值强度` 从 0 拖到 100，盯着**有效电平数**和**MSE**：MSE 一路涨，SQNR 会先跌后涨
3. 把 `粒度` 切到 `group-wise`，groupSize 设 32，看 SQNR 跳多少 dB
4. 把 `编码` 切到 `NF4`，对比同粒度的对称 INT4
5. 把 `位数` 从 2 拖到 8，看 SQNR 怎么涨、字节/权重怎么掉，找到那个"再压就不划算"的位置
6. 最后看「显存账」那张表，把 groupSize 改成 8 看看量化收益是怎么被元数据吃光的
